# ДЗ № 4. Сбор метрик приложения в VictoriaMetrics

## 1. Стек

- **Приложение:** Task Manager на Java 25 и Spring Boot 4.1.1.
- **Метрики приложения:** Spring Boot Actuator и Micrometer Prometheus Registry.
- **База данных:** PostgreSQL 16.
- **Экспорт метрик PostgreSQL:** `postgres-exporter` версии `v0.17.1`, работающий отдельным контейнером в Pod PostgreSQL и доступный на порту `9187`.
- **Оркестрация:** Kubernetes в Minikube.
- **Сбор метрик:** VictoriaMetrics Agent (`vmagent`), установленный через Helm.
- **Хранение и запрос метрик:** VictoriaMetrics Single, установленная через Helm.

VictoriaMetrics и vmagent установлены в namespace `metrics`. Приложение и PostgreSQL с экспортером работают в namespace `default`.

## 2. Экспорт метрик приложения

В проект подключены `spring-boot-starter-actuator` и `micrometer-registry-prometheus`. В `src/main/resources/application.yml` для веб-доступа Actuator открыты endpoints `health`, `info` и `prometheus`.

Метрики приложения доступны по адресу:

```text
/actuator/prometheus
```

В `k8s/app-deployment.yaml` для Pod приложения заданы аннотации, используемые для обнаружения цели сбора:

```yaml
prometheus.io/scrape: "true"
prometheus.io/port: "8080"
prometheus.io/path: "/actuator/prometheus"
```

Во время проверки в VictoriaMetrics успешно отображалась метрика JVM `jvm_memory_used_bytes`, в том числе для областей памяти `heap` и `nonheap`. Это подтверждает экспорт метрик JVM.

## 3. Бизнес-метрики Task Manager

В сервисе `TaskService` используются счётчики Micrometer для операций с задачами. Во время проверки через интерфейс VictoriaMetrics были обнаружены следующие метрики:

| Метрика в VictoriaMetrics | Назначение |
|---|---|
| `tasks_list_requests_total` | Количество обращений за списком задач. |
| `tasks_updated_total` | Количество обновлений задач. |
| `tasks_deleted_total` | Количество удалений задач. |
| `tasks_total` | Метрика, отображавшаяся в работающем экземпляре приложения и отражавшая количество задач. |

После выполнения действий в веб-интерфейсе Task Manager значения бизнес-метрик изменялись, что было видно в VictoriaMetrics.

**Примечание о названии метрики:** в локальном исходном коде `TaskService.java` создание задачи увеличивает счётчик с именем `tasks_created`, тогда как в работающем экземпляре VictoriaMetrics во время проверки отображалась метрика `tasks_total`. Это расхождение между локальным исходником и запущенным образом не исправлялось в рамках данной проверки.

## 4. Экспорт метрик PostgreSQL

Для экспорта метрик PostgreSQL используется `prometheuscommunity/postgres-exporter:v0.17.1`. Контейнер экспортера добавлен в Pod PostgreSQL и слушает порт `9187` по пути `/metrics`.

Для обнаружения экспортера в `k8s/postgres-deployment.yaml` указаны аннотации:

```yaml
prometheus.io/scrape: "true"
prometheus.io/port: "9187"
prometheus.io/path: "/metrics"
```

Работа экспортера проверена запросами в VictoriaMetrics:

- `up` — цель `postgres-exporter` имела значение `1`;
- `pg_up` — значение `1`, то есть экспортер мог подключиться к PostgreSQL;
- `pg_stat_database_numbackends` — метрика числа подключений к базам данных отображалась, в том числе для базы `taskdb`.

## 5. Service discovery и передача метрик

Сбор метрик выполняется через `vmagent`. В его конфигурации используется Kubernetes service discovery для Pod (`role: pod`), а правила отбора используют аннотации `prometheus.io/scrape`, `prometheus.io/port` и `prometheus.io/path`.

Полученные метрики отправляются в VictoriaMetrics по `remoteWrite`. В конфигурации vmagent указан адрес записи:

```text
http://vm-victoria-metrics-single-server.metrics.svc.cluster.local:8428/api/v1/write
```

В ходе проверки запрос `up` в VictoriaMetrics показал, что цели `task-manager` и `postgres-exporter` доступны и в момент проверки имели значение `1`.

## 6. Команды проверки

Посмотреть Pod мониторинга:

```powershell
kubectl get pods -n metrics
```

Посмотреть сервисы мониторинга:

```powershell
kubectl get svc -n metrics
```

Открыть веб-интерфейс VictoriaMetrics через проброс порта:

```powershell
kubectl port-forward svc/vm-victoria-metrics-single-server -n metrics 8428:8428
```

В браузере открыть:

```text
http://localhost:8428/vmui/
```

Проверить состояние целей сбора запросом:

```promql
up
```

Проверить метрики JVM:

```promql
jvm_memory_used_bytes
```

Проверить доступность PostgreSQL для экспортера:

```promql
pg_up
```

Проверить метрики базы данных PostgreSQL:

```promql
pg_stat_database_numbackends
```

Проверить бизнес-метрики приложения:

```promql
{__name__=~"tasks_.*"}
```

## 7. Результат

VictoriaMetrics и vmagent запущены в Minikube. Через интерфейс VictoriaMetrics подтвержден сбор метрик JVM, PostgreSQL и бизнес-метрик Task Manager. Цели приложения и PostgreSQL exporter обнаруживаются через Kubernetes service discovery с использованием аннотаций `prometheus.io/*`.
